# ADR 0001: Project name and CLI name

- Status: accepted; applied at the start of Phase 1 (2026-10-16)
- Date: 2026-10-16
- Phase: 0

## Context

SPEC §0 uses "Switchyard" (CLI `sy`) as a working name and asks Phase 0 to check it on the
package index and on code hosting, and to propose three alternatives if it is taken. The check
(docs/RESEARCH.md, "Name check", verified 2026-10-16) found:

- The package-index name `switchyard` belongs to an unrelated networking framework, so
  `uv tool install switchyard` would install the wrong project.
- An active, widely starred open-source LLM model-routing library named Switchyard (created
  2026-05) works on the same problem: format translation and routing for coding agents.
- An npm package `switchyard-ai`, published 2026-09-25 as a routing and cost layer for AI
  coding agents, installs executables named `switchyard` **and `sy`**. A file-sync crate also
  installs `sy`.

Keeping the name would confuse users with a same-domain project and collide on the CLI.

## Options

| Option | Package index / npm | Code host | CLI | Assessment |
|---|---|---|---|---|
| Keep Switchyard (`sy`) | taken / taken | same-domain project | `sy` collides with a same-domain tool | rejected |
| **Stepswitch** (`ssw`, long form `stepswitch`) | free / free | 4 small repos, no product | `ssw` free (the index package of that name is a library with no command) | **chosen** |
| Shuntyard (`sy`) | free / free | algorithm exercises only | keeps `sy`, with the collisions above | runner-up |
| Signalyard (`sy`) | free / free | 2026 observability repos | keeps `sy` | weaker: suggests observability tooling |

Also checked and rejected: stepyard, yardmaster, railyard, turnout (taken), modelyard (AI
gateway repos), sortyard and routeyard (unexplained recent repos).

## Decision

Rename the project to **Stepswitch**: distribution and import name `stepswitch`, CLI `ssw` with
`stepswitch` as an alias. The name describes the headline feature, step-level model switching.

The rename is applied as the first change of Phase 1, before any package code exists:
distribution, import package, CLI, local state directory (`.switchyard/` becomes `.stepswitch/`),
config file (`switchyard.toml` becomes `stepswitch.toml`), egress module, the contracts in
`scripts/phase_check.py`, and the docs. Phase 0 documents keep the working name so that this
decision can still be reversed at no cost. Claim texts do not contain the name and are unaffected.

## Consequences

- Commands in the kickoff goal lines change from `sy ...` to `ssw ...` from Phase 1 on.
- If the maintainer prefers to keep `sy`, Shuntyard is the runner-up and the same rename applies
  with a different string; the collisions noted above remain.
- The package-index and npm names should be registered by the maintainer before any public
  announcement. Registration is a maintainer action, not something automation does.
